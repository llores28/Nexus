The Solution: ask_user_question Tool
How we make model selection interactive
❌ Old Approach (Passive)

Rule just said "suggest Claude for expert tasks":

  • Cascade reads rule silently
  • Maybe mentions it in text (easy to miss)
  • No interactive choice
  • User doesn't know to switch
✅ New Approach (Interactive)

Rule instructs Cascade to USE ask_user_question:

  • Cascade detects complex task
  • Calls ask_user_question tool
  • Clickable buttons appear
  • User picks model with one click

Key insight: Cascade has the ask_user_question tool (same as Plan mode choices). We just needed to instruct the rule to USE it!

pre-push Hook
On Every git push
Regenerates state-dashboard.html before code leaves your machine

Cascade Rule
After Each Edit
01-project-state.md instructs Cascade to call journal log after significant changes
1
One-time setup per project
journal session-start → journal setup-hooks → VS Code prompts Allow auto tasks
2
State written to .nexus/state.md
Plain Markdown — readable by Cascade (Windsurf indexed), Claude Code, Cursor, or any agent that reads project files
3
Cascade reads state before every edit
Rule 01-project-state.md (always_on) tells Cascade: check What's Done — do NOT revert recent fixes
Regression guard
4
Session close via /session-handoff
diff → session-end (prompts summary + next tasks) → export dashboard HTML → handoff block for next session
